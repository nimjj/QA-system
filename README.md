# laya-finetuning

Fine-tune Laya's English checkpoint so it can replace Ollama in the QA grading pipeline (`qa-analysis`).
Everything is synthetic, so results are reported as "good on realistic synthetic calls", not "proven on real calls".

The full plan (phases, data volumes, success criteria) is in [`docs/DATA_PLAN.md`](docs/DATA_PLAN.md).

## What runs where

| Where | What |
|---|---|
| **Google Colab (L4 GPU)** | the notebooks `0x_*.ipynb`: install, download base, train, evaluate |
| **Your PC (CPU)** | `tools/*.py`: data building, validation, local checks. Use the `qa-analysis` venv |
| **Google Drive** `MyDrive/laya-finetuning/` | checkpoints, datasets, run reports (Colab's disk is wiped at session end) |
| **Git (this repo)** | notebooks, tools, prompts, docs, small data files. **Never** weights |

The original Laya checkpoint is never modified. Training reads a downloaded copy and writes a **new** folder.

## Plan A: smoke test (this is what exists today)

Goal: prove install, download, dry-run, train, reload, predict, save to Drive, and load on local CPU all work, on 20 dummy rows. It says nothing about quality.

1. **Colab:** open `00_smoke_test.ipynb`, run the cells top to bottom. Each cell begins with a comment saying what you should see. Paste anything unexpected back.
2. **Download** from Drive `laya-finetuning/checkpoints/<run id>/` to `checkpoints/<run id>/` here: the `final/` folder and `files/smoke_preds_ft.json`.
3. **Local check (PowerShell, from this folder):**
   ```powershell
   ..\qa-analysis\.venv\Scripts\python.exe tools\check_local_load.py `
       --checkpoint checkpoints\<run id>\final --preds checkpoints\<run id>\files\smoke_preds_ft.json
   ```
   `PASS` means the checkpoint serves through `qa-analysis`'s `laya_adapter` on CPU and matches Colab within 0.03.

To serve any fine-tuned checkpoint in `qa-analysis`, set `LAYA_CHECKPOINT` to its folder before starting the service (unset = stock model). `.env` is not edited.

## Tools

| File | Purpose |
|---|---|
| `tools/export_checks.py` | freezes the production `LAYA_CHECKS` questions + word caps into `data/frozen/checks_frozen.json` with a sha256 (`--check` tells you if qa-analysis has drifted) |
| `tools/smoke_rows.py` | the 20 smoke rows, built from the frozen questions |
| `tools/smoke_cells/` | the notebook cells as small readable files |
| `tools/build_smoke_notebook.py` | assembles `00_smoke_test.ipynb` from those cells (embeds the frozen questions and rows). Re-run it after changing a cell |
| `tools/check_local_load.py` | the local CPU check above |
| `tools/laya_train_cuda.py` | `laya-train` with a fix for a laya 0.4.0 bug that crashes training on any GPU. **Use this instead of `laya-train` on Colab** |

## Rules that keep the data honest
- Question wording and every extractor are **frozen** before data is generated. Change one and the data must be regenerated.
- Splits are by **call and by pair**, never by row.
- The test set is generated by a different model (Gemini) and labelled by hand. It is scored once.
